CSS-enheter

Pixlar, procent, em, rem, vw och vh. Små val som avgör om sidan är stel – eller följer skärmen och användaren.

Mål: kunna skilja på absoluta och relativa enheter och välja rätt enhet för text, layout och detaljer. Under lektionen: många små övningar.

Översikt

Två familjer av enheter

Absoluta enheter

Har en fast storlek som inte ändras av sammanhanget.

px – den enda vi använder på webben. pt, cm, in hör till tryck.

Relativa enheter

Räknas ut från något annat: föräldern, fontstorleken eller fönstret.

% em rem vw vh vmin
Dagens fråga

När är fast bättre än flexibelt – och tvärtom?

px · absolut enhet

Pixlar – exakthet

1px är 1/96 av en tum och har alltid samma storlek, oavsett element och fönster.

border: 2px solid #333;                     /* exakt ram */
box-shadow: 0 4px 8px rgba(0,0,0,.1);       /* exakt skugga */
margin-top: 24px;                           /* exakt avstånd */
Använd px till

Borders, skuggor och små detaljer. Inte till text och stora layouter.

Övning 1 · px

Testa pixlar

1

Bygg en låda med border: 2px solid; och margin: 24px;. Ändra till 1px och sedan 4px – vad förändras?

2

Lägg till box-shadow: 0 4px 8px rgba(0,0,0,.1);. Testa 0 2px 4px i stället – vilken känns rätt?

3

Dra i webbläsarfönstret. Ändras kanten eller skuggan? Varför inte?

Kontroll

Kanten och skuggan står still oavsett fönsterstorlek – det är det absoluta.

% · relativt föräldern

Procent – av förälderns bredd

.container {
  width: 80%;         /* 80 % av förälderns bredd */
  max-width: 1200px;  /* men aldrig mer */
  margin: 0 auto;     /* centrera */
}
Förälder (100 %)
Barn: width 80 %
Kom ihåg

Procent räknas alltid från föräldern. Ändra förälderns bredd och barnet följer med. (float i äldre exempel är historisk layout – Flexbox och Grid kommer senare.)

Övning 2 · %

Testa procent

1

Lägg en låda med width: 80%; inuti en förälder. Ändra till 50% – hur mycket mer tom yta blir det i föräldern?

2

Ge föräldern width: 60%;. Följer barnet med när föräldern krymper?

3

Lägg till max-width: 600px; och margin: 0 auto; på en container. Vad händer i ett smalt fönster – och i ett brett?

Kontroll

% + max-width gör sidan flexibel men aldrig bredare än du vill.

em · relativt förälderns font

em – relativt texten omkring

1em = förälderns font-size. Är föräldern 20px är 1em = 20px.

.parent { font-size: 20px; }
.child {
  font-size: 1.5em;  /* 30px */
  padding: .5em;     /* 15px – EGEN font */
}
Förälder 20px
Barn 1.5em = 30px
Nesting-problemet

em ärver sammanhang: 1.2em inuti 1.2em blir 1.44. Därför är rem oftast tryggare.

Övning 3 · em · förutsäg

Räkna med em

Föräldern är 20px. Barnet har font-size: 1.5em; och padding: .5em;. Hur stor blir texten – och hur stor blir paddingen?

Text: 1.5 × 20 = 30px.

Padding: .5 × 30 = 15px – padding räknas på elementets egen fontstorlek.

Följdfråga: ändra föräldern till 24px. Vad händer? (Text 36px, padding 18px.)

rem · relativt root

rem – relativt rotfonten

1rem = html-elementets fontstorlek. Standard i webbläsaren är 16px.

.heading {
  font-size: 2rem;      /* 32px */
  margin-bottom: 1rem;  /* 16px */
}
.small-text {
  font-size: .875rem;   /* 14px */
}

2rem = 32px

1.25rem = 20px

.875rem = 14px

Därför rem

Förutsägbar, påverkas inte av nesting och respekterar användarens inställningar. Första valet för text och spacing.

Övning 4 · rem

Testa rem

1

Gör om margin: 24px;, padding: 16px; och font-size: 20px; till rem. Utgå från 16px root.

2

Lägg till html { font-size: 20px; } tillfälligt. Vad händer med allt som är satt i rem?

3

Ta bort regeln igen. Varför är det en fördel att sidan skalar med användarens inställning?

Kontroll

24px = 1.5rem · 16px = 1rem · 20px = 1.25rem. Med 20px root blir 1rem plötsligt 20px – hela sidan följer med.

Övning 5 · em vs rem · förutsäg

Samma kod – olika resultat?

/* A */ .parent { font-size: 1.2em; }  .child { font-size: 1.2em; }
/* B */ .parent { font-size: 1.2rem; } .child { font-size: 1.2rem; }

Roten är 16px. Hur stor blir .child i A respektive B?

A: 1.2 × 1.2 × 16 = 23,04px – em multipliceras genom leden.

B: 1.2 × 16 = 19,2px – rem räknas alltid från roten.

Samma siffror i koden, olika resultat. Det är därför rem rekommenderas.

vw · vh · vmin · vmax

Enheter för fönstret

vw1vw = 1 % av fönstrets bredd
vh1vh = 1 % av fönstrets höjd
vmin1 % av den mindre sidan (bredd eller höjd)
vmax1 % av den större sidan
.hero   { height: 100vh; }
.square { width: 50vmin; height: 50vmin; }
h1      { font-size: clamp(1.5rem, 5vw, 3rem); }  /* skalas men begränsas */
width: 30vw – ändra fönstrets bredd och se
Mobilfällan

Undvik height: 100vh på mobil – verktygsfältet ändrar höjden. Använd min-height: 100vh.

Vanliga misstag

Gör inte så här

✗em för allt – 1.2em inuti 1.2em blir 1.44, inte 1.2.
✓rem för förutsägbarhet – räknas alltid från roten.
✗height: 100vh på mobil – verktygsfältet ger scrollbars.
✓min-height: 100vh – minst full höjd, utan att låsa.
✗px på allt – stel sida som ignorerar användarens inställningar.
✓rem och % för text och layout – sidan följer med.
Övning 8 · rätta enheterna

Gör den stela CSS:en flexibel

Koden fungerar – men den är stel. Byt till lämpliga enheter.

.card {
  width: 400px;            /* ska vara flexibel upp till 400px */
  padding: 24px;           /* ska skala med texten */
  border: 1px solid #ccc;  /* behåll */
  margin-bottom: 32px;
}
h2 { font-size: 20px; }    /* ska följa användarens inställning */
.hero { height: 900px; }   /* ska vara minst full skärmhöjd */
.card { width: 100%; max-width: 400px; padding: 1.5rem;
        border: 1px solid #ccc; margin-bottom: 2rem; }
h2    { font-size: 1.25rem; }
.hero { min-height: 100vh; }
